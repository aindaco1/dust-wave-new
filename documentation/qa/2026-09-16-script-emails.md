# Script submission and approval email — September 16, 2026

The Community Worker adds three Resend transactional messages: a writer receipt
for a new public script submission, an individual review notice to every current
Community admin, and a writer confirmation on first approval. Writer messages
retain the submission form's English/Spanish language; admin notices use English.
The [Worker guide](../../workers/community/README.md#script-notification-emails)
owns the configuration, delivery policy, failure handling and rollback procedure.

## Source and local checks

- `npm run test:community` passed: 15 public/browser contracts, 24 admin browser
  tests, 40 Worker tests, and a dependency audit with no vulnerabilities.
- Email tests exercise real isolated D1 transactions with fake provider responses:
  duplicate/concurrent submissions, first-approval semantics, rollback, all 100
  possible admin recipients, immutable retries, leases, lost responses, permanent
  failures, rate limits, the retry window, and local/staging recipient restrictions.
- `npm run check:podcasts` passed, including the pin/security/dependency checks,
  Podcast validation and module syntax checks. The staged-source credential scan
  and `git diff --check` also passed.
- `npm run build:community-staging` passed the production WebP pipeline and
  prepared the six staging shells. Wrangler dry-run and generated binding types
  validated the Worker configuration without changing the Platform pin.
- An existing synthetic drag test failed in both the unchanged checkout and this
  branch at 320 pixels: default `clientY=0` selected the wrong half of a scrolled
  target. The fixture now scrolls its target into view and explicitly drops near
  its top edge. Production drag code was not changed; the full admin suite passed.

## Provider simulation

Five messages generated by the actual application templates/outbox were sent
through a local isolated D1 dispatcher with the staging sending-only key. All
recipients were Resend's `delivered@resend.dev` simulator. No actual writer/admin
received a test, and no fixture scripts were inserted into remote D1 or R2.

Resend reported `delivered` for the English receipt, admin notice, English approval,
Spanish receipt and Spanish approval. Their sender was **Dust Wave Writers Group
<community@dustwave.xyz>**, with replies to **info@dustwave.xyz**. This verifies the
provider simulation, templates, credentials and dispatcher transport; it does not
establish delivery or authentication headers in an actual recipient's inbox.

## Deployment

Migration `0004_script_email_outbox.sql` adds only the outbox and its index. It
does not queue messages for existing submissions or change the user directory.
Separate domain-restricted sending keys are provisioned for staging and production.
Staging retains its simulator-only recipient allowlist; local mode cannot send.

Staging Worker version: `e2967bca-dee8-408a-b6b8-7f0aaac54c88`. The five-minute
email retry trigger is separate from the existing daily schedule/cleanup trigger.
Deployment and public/private-route smoke results are recorded with the release
follow-up; they remain separate from the provider simulation above.
